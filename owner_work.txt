TASK 2: SUPABASE PROJECT SETUP (15 minutes)
============================================================

Step 2.1 — Create a Supabase account/project
  1. Go to: https://supabase.com
  2. Sign in with GitHub (or create an account)
  3. Click "New Project"
  4. Fill in:
     - Project name: hireready
     - Database password: (save this somewhere safe!)
     - Region: pick the closest to India (e.g., "South Asia (Mumbai)")
  5. Click "Create new project"
  6. Wait 1-2 minutes for it to set up

Step 2.2 — Get your API keys
  1. In Supabase dashboard, go to: Settings > API
     (left sidebar > gear icon > API)
  2. Copy these two values:
     - "Project URL" → this is your SUPABASE_URL
     - "anon public" key (under Project API Keys) → this is your SUPABASE_ANON_KEY
  3. Open ~/Documents/Projects/hireready/.env.local
  4. Replace the placeholder values:
     NEXT_PUBLIC_SUPABASE_URL=https://xxxxx.supabase.co
     NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIs...

Step 2.3 — Run the database schema
  1. In Supabase dashboard, go to: SQL Editor
     (left sidebar > database icon > SQL Editor)
  2. Click "New Query"
  3. Open this file on your computer:
     ~/Documents/Projects/hireready/supabase-schema.sql
  4. Copy ALL the content and paste it into the SQL editor
  5. Click "Run" (or Cmd+Enter)
  6. You should see "Success. No rows returned" — that's correct!
  7. Verify: Go to "Table Editor" in sidebar, you should see these tables:
     - profiles
     - resumes
     - analyses
     - chat_messages
     - applications
     - saved_jobs

Step 2.4 — Create storage bucket for resume uploads
  1. In Supabase dashboard, go to: Storage
     (left sidebar > folder icon)
  2. Click "New Bucket"
  3. Name: resumes
  4. Toggle OFF "Public bucket" (keep it private)
  5. Click "Create bucket"
  6. Click on the "resumes" bucket > "Policies" tab
  7. Click "New Policy" > "For full customization"
  8. Create these 2 policies:

  Policy 1 - Upload:
    Name: "Users can upload resumes"
    Allowed operation: INSERT
    Target roles: authenticated
    WITH CHECK expression:
      bucket_id = 'resumes' AND auth.uid()::text = (storage.foldername(name))[1]

  Policy 2 - Read:
    Name: "Users can read own resumes"
    Allowed operation: SELECT
    Target roles: authenticated
    USING expression:
      bucket_id = 'resumes' AND auth.uid()::text = (storage.foldername(name))[1]

Step 2.5 — Enable Email Auth (already enabled by default)
  1. Go to: Authentication > Providers
  2. Make sure "Email" is enabled
  3. Under Email settings:
     - Enable "Confirm email" (recommended for production)
     - OR disable it for faster testing during development


============================================================
TASK 3: GOOGLE OAUTH SETUP (10 minutes)
============================================================

Step 3.1 — Create Google OAuth credentials
  1. Go to: https://console.cloud.google.com
  2. Create a new project (or use existing):
     - Click the project dropdown at top > "New Project"
     - Name: HireReady
     - Click "Create"
  3. Go to: APIs & Services > Credentials
     (left sidebar > "APIs & Services" > "Credentials")
  4. Click "Configure Consent Screen" (if asked):
     - User Type: External
     - App name: HireReady
     - User support email: your email
     - Developer contact: your email
     - Click "Save and Continue" through all steps
  5. Go back to Credentials page
  6. Click "+ CREATE CREDENTIALS" > "OAuth client ID"
  7. Application type: "Web application"
  8. Name: HireReady Web
  9. Under "Authorized redirect URIs", add:
     https://XXXXXX.supabase.co/auth/v1/callback
     (Replace XXXXXX with your actual Supabase project URL from Task 2)
  10. Click "Create"
  11. Copy the "Client ID" and "Client Secret"

Step 3.2 — Add Google credentials to Supabase
  1. In Supabase dashboard, go to: Authentication > Providers
  2. Find "Google" and expand it
  3. Toggle it ON
  4. Paste your:
     - Client ID (from step 3.1)
     - Client Secret (from step 3.1)
  5. Click "Save"

============================================================
TROUBLESHOOTING
============================================================

Q: "Google sign-in doesn't work"
A: Check that the redirect URI in Google Console exactly matches
   your Supabase callback URL. Common mistake: missing /auth/v1/callback

Q: "Resume upload fails"
A: Make sure you created the "resumes" storage bucket and added
   the policies in Step 2.4

Q: "AI analysis returns an error"
A: Check your HF_TOKEN is valid. Test it by running:
   curl -H "Authorization: Bearer YOUR_HF_TOKEN" \
   https://router.huggingface.co/v1/models

Q: "Tables not found"
A: Re-run the supabase-schema.sql in the SQL Editor. Make sure
   you ran ALL of it, not just part of it.
